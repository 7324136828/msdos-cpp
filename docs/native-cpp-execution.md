# Native C++ execution

All 38 generated translation units execute through compiled C++ statements, labels, conditional branches, and loops. The generator no longer emits an instruction-by-instruction `while`/`switch(pc)` executor. `Machine::tick()`, its instruction counter, and its instruction budget have been removed. Original line references remain comments alongside source and include hashes.

An assembly conditional branch now becomes an ordinary compiled C++ conditional branch:

```cpp
if (m.flags.carry) goto dos_EXIT_20;
```

Straight-line instructions fall through as C++ statements. REP is a normal C++ loop. The compiler emits the host's native machine instructions for these operations. No runtime fetches or decodes a translated instruction index before executing each statement.

## DOS state and ABI

`Machine` supplies DOS register values, 8/16-bit arithmetic and flags, segmented memory, a DOS stack, and explicit interrupt callbacks. These preserve the original observable behavior: byte registers alias words, arithmetic wraps, stack arguments can point to aliased memory, and DOS/BIOS services return through registers and flags. This compatibility state remains part of the API; the source transcription has not been rewritten into a completely register-free, typed application API.

The 30 DOS 4.0 mapper bodies have no internal CALL instructions. Their generated returns clean up the far DOS call frame and parameters, validate the wrapper return token, then use C++ `return`. Their actual DOS/BIOS service implementation remains an external dependency.

Some older modules use internal calls and indirect jumps. Direct CALLs push a relocated DOS return token and branch to compiled C++ code. A bounded switch handles only the return tokens generated by those calls. TRANS's opcode-table jump also selects among compiled labels. These are the source's dynamic control transfers, rather than a dispatcher for every instruction.

This retains TRANS's nonlocal control flow: its error recovery jumps out of nested source routines and resets SP. Substituting ordinary recursive C++ function calls would leave native call frames that the DOS stack reset cannot unwind. The generated labels and DOS return tokens preserve the original behavior without such recursion.

Invalid dynamic targets throw an exception. Interrupt callbacks that set `m.halted` stop execution before the next source statement. An already halted machine skips the translated body after its existing export wrapper setup.

## Validation

All eight CTest groups pass. Dedicated native-control-flow fixtures check nested/shared returns, conditional return blocks, indirect tables, invalid jump and return tokens, interrupt/CALL-5 termination, initially halted entries, REP count/direction/wrapping, and a stack reset that bypasses two nested calls.

Existing exhaustive arithmetic, FAT/FCB, COMMAND, and mapper tests check the DOS state contracts. TRANS tests compare exact output bytes with fixtures captured using the previous executor across its 20 opcode-table handlers and recovery from an invalid opcode. Generated-file tests verify reproducibility from the original source.

The boot kernel already executes native guest COM instructions in VirtualBox. This host translation change does not modify the boot image or complete the DOS 4.0 kernel port.
